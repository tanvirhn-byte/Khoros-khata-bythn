3. COMPLETE LIST OF ISSUES FOUND
================================================================================

Issue #1 — [CRITICAL] Frontend Runtime Crash on Authenticated View Rendering
- Area        : Frontend Application Logic
- File(s)     : `/khoroch/index.html`, `/public/khoroch/index.html`,
                `/android/app/src/main/assets/public/index.html`
- Description : Calling `go()` when authenticated threw `ReferenceError: tab is
                not defined` / `ReferenceError: cur is not defined`, and calling
                `tc()` before line 1660 threw a Temporal Dead Zone error on `SK`.
- Root Cause  : Top-level state variables `cur`, `tab`, `F`, and `R` were missing
                their `let` declaration before `go()`, and `FIRST`, `IDLE`, and
                `SK` were declared ~130 lines after `tc` referenced `SK`.
- Impact      : Complete crash of Dashboard, Expense List, Reports, Categories,
                and Settings views after login.

Issue #2 — [HIGH] GitHub Actions Cloud APK Build Failure at Step 8 (`Set up Android SDK`)
- Area        : GitHub Actions & Cloud Build
- File(s)     : `/.github/workflows/android-build.yml`
- Description : In GitHub Actions Run #4 (`41123104392` on commit `209d0e9`),
                Steps 1–7 (`Checkout`, `Set up Node.js 22`, `Install Node.js
                dependencies`, `Synchronize Capacitor web assets`, `Verify
                Android web assets`, `Set up Temurin JDK 17`) all succeeded,
                but Step 8 (`Set up Android SDK`) failed with exit code 1.
- Root Cause  : `android-actions/setup-android@v3` defaults to running
                `sdkmanager "tools" "platform-tools"`. Google removed the
                obsolete `tools` package from the Android SDK repository on
                `ubuntu-latest` (`Warning: Failed to find package 'tools'`).
- Impact      : Prevented the cloud workflow from reaching `./gradlew assembleDebug`
                and generating `khoroch-debug-apk`.

Issue #3 — [HIGH] Dangling Token Bypass When User Record Is Missing
- Area        : Authentication & Authorization
- File(s)     : `/khoroch/api.php`, `/public/khoroch/api.php`
- Description : During token authentication (`api.php` line 297), user status was
                checked via `if ($stt !== false && $stt !== 'active')`.
- Root Cause  : If a user row was deleted from `users` while a token row still
                existed in `tokens`, `$uChk->fetchColumn()` returned `false`,
                bypassing the `if ($stt !== false && ...)` block and allowing the
                request to proceed with a nonexistent `$uid`.
- Impact      : Orphaned tokens were not rejected or cleaned up, allowing ghosts
                to write orphaned rows into `groups_`, `categories`, or `expenses`.

Issue #4 — [HIGH] Sync Rejection Loop on Deleted Tombstones (`deleted=1`)
- Area        : Online Synchronization & Offline Data Handling
- File(s)     : `/khoroch/api.php`, `/public/khoroch/api.php`,
                `/khoroch/index.html`, `/public/khoroch/index.html`
- Description : When a user deleted a category or expense whose parent group was
                also deleted or did not exist on the server, `api.php` pushed its
                ID into `$rejected['categories']` / `$rejected['expenses']`.
- Root Cause  : `api.php` treated `deleted=1` tombstones with missing/deleted
                groups as rejected records instead of acknowledging the deletion,
                and the client marked `_rej=1` on deleted tombstones.
- Impact      : Client displayed a persistent sync rejection error (`গ্রুপ না থাকায়
                Xটি খরচ সিঙ্ক হয়নি`) for already-deleted items that the user could
                no longer see or fix in the UI.

Issue #5 — [MEDIUM] Incomplete Field Change Detection During Sync Merge
- Area        : Online Synchronization
- File(s)     : `/khoroch/index.html`, `/public/khoroch/index.html`
- Description : When merging server records in `sync()`, `ch` (which triggers
                `go()` UI re-render) only checked `name`, `amt`, `deleted`, `v`,
                and `cats`.
- Root Cause  : Edits to an expense's description (`desc`), note (`note`), date
                (`dt`), time (`tm`), group (`pid`), or a category's `parent` on
                another device updated `S` in memory when `i.updated >= l.updated`,
                but did not set `ch = true`.
- Impact      : UI did not immediately re-render when description, date, time,
                note, or parent category changed on another device.

Issue #6 — [MEDIUM] Missing CSS Rules for Notices, Social Icons, File Input & Maintenance
- Area        : Frontend UI & Styling
- File(s)     : `/khoroch/index.html`, `/public/khoroch/index.html`
- Description : 15+ CSS selectors used by JavaScript templates had no rules in
                `<style>`: `.nt`, `.nt-info`, `.nt-success`, `.nt-warning`,
                `.nt-danger`, `.ntb`, `.card.ntc`, `.nbar a`, `.nbar button`,
                `.soc`, `.soc a`, `.soc a svg`, `#mt`, `.mtc`, `.mti`,
                `label.fl`, `label.fl input[type="file"]`, `.row2`, `.grp .gname`,
                `.gh`, and `.ph`.
- Root Cause  : Styles were omitted during earlier UI consolidation.
- Impact      : Unstyled inline SVG social icons rendered huge, maintenance mode
                (`#mt`) rendered inline at the bottom of the page instead of a
                fullscreen lock overlay, and raw `<input type="file">` appeared
                inside the JSON restore button.

Issue #7 — [MEDIUM] Admin Panel Session Purge Policy Mismatch & Missing UI Controls
- Area        : Admin Panel
- File(s)     : `/khoroch/admin.php`, `/public/khoroch/admin.php`
- Description : `admin.php`'s `purge` action deleted tokens using `created < ?`
                (90 days since login creation) instead of `COALESCE(last_seen, created) < ?`
                (90 days of inactivity, as used in `api.php`), and the backend
                `kick` and `purge` actions had no buttons in the Admin Panel HTML.
- Root Cause  : `admin.php` was not updated when `last_seen` sliding expiration
                was added to `api.php`.
- Impact      : Active users logged in for >90 days would have their sessions
                prematurely purged by admin maintenance, and admins could not
                invoke `kick` or `purge` from the UI.

Issue #8 — [MEDIUM] Malformed `ignoreAssetsPattern` in Android `build.gradle`
- Area        : Android Project & Gradle Configuration
- File(s)     : `/android/app/build.gradle`
- Description : Line 16 specified `:!:*.php:!:*.sqlite:!:*.sqlite-wal...` with
                an extra colon after each `!`.
- Root Cause  : Typo in AAPT `ignoreAssetsPattern` syntax (AAPT expects `:` as
                delimiter and `!` as negation prefix, i.e., `:!*.php`).
- Impact      : AAPT treated patterns as literal `:*.php` instead of excluding
                `*.php` and `*.sqlite` if any were present in assets.

Issue #9 — [MEDIUM] Missing Tracked `data/.htaccess` and `data/index.php` Guard Files
- Area        : Security & Repository Configuration
- File(s)     : `/.gitignore`, `/khoroch/data/.htaccess`, `/khoroch/data/index.php`,
                `/public/khoroch/data/.htaccess`, `/public/khoroch/data/index.php`
- Description : `.gitignore` ignored `khoroch/data/` and `public/khoroch/data/`
                entirely, so the static directory protection files (`data/.htaccess`
                and `data/index.php`) were missing from the repository.
- Root Cause  : Overly broad directory ignore rule in `.gitignore`.
- Impact      : Fresh clones or deployments without first hitting `api.php`
                lacked static `data/.htaccess` and `data/index.php` files, and
                failed Phase 13 security test checks.

7. SECURITY, PRIVACY & DATA INTEGRITY ASSESSMENT
================================================================================
- Authentication & Session Security:
  - Passwords hashed with `PASSWORD_DEFAULT` (bcrypt/argon2); rehashed transparently
    via `password_needs_rehash()`.
  - Bearer tokens generated with `random_bytes(30)` (60-char hex) and stored as
    SHA-256 hashes (`hash('sha256', $rawToken)`) in `tokens`.
  - Tokens extracted strictly from `Authorization: Bearer`, JSON body, or POST
    body—never from `$_GET`.
  - Dangling tokens for deleted/nonexistent users are now immediately revoked and
    rejected with HTTP 401.
- Multi-User Data Isolation:
  - Every data table (`groups_`, `categories`, `expenses`, `prefs`) uses composite
    `PRIMARY KEY (user_id, id)` and scopes all `SELECT`, `INSERT OR REPLACE`,
    and `DELETE` statements by authenticated `user_id`.
- XSS, CSRF & Transport Security:
  - Frontend escapes all user-supplied strings with `esc()` and validates URLs
    with `okU()` / `okS()`.
  - Admin Panel enforces `hash_equals($_SESSION['csrf'], ...)` on all POST actions
    and `session_regenerate_id(true)` on login.
  - Native Android enforces `cleartextTrafficPermitted="false"`,
    `MIXED_CONTENT_NEVER_ALLOW`, `setAllowFileAccess(false)`, and
    `setWebContentsDebuggingEnabled(false)`.
- Repository Privacy:
  - Zero `.sqlite`, `.log`, `.env`, or `.jks`/`.keystore` files are tracked in Git.
