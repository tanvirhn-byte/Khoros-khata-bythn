১. প্রজেক্টের পরিচিতি ও স্থাপত্য (Architecture)
================================================================================
"খরচের খাতা" হলো একটি আধুনিক, হালকা, অফলাইন-ফার্স্ট ব্যক্তিগত ও পারিবারিক খরচ 
ব্যবস্থাপনা অ্যাপ্লিকেশন। এটি তিনটি মাধ্যমে সমান দক্ষতায় কাজ করতে পারে:
  ক) সাধারণ ওয়েবসাইট (যেকোনো ব্রাউজারে)
  খ) PWA (Progressive Web App - কোনো APK ছাড়াই ফোনে ইনস্টল করা যায়)
  গ) Native Android App (পূর্ণাঙ্গ ইনস্টলেবল .apk ফাইল)

অ্যাপটি এমনভাবে ডিজাইন করা হয়েছে যাতে ফোনে ইন্টারনেট না থাকলেও সব হিসাব নিখুঁতভাবে 
সেভ থাকে এবং হিসাব-নিকাশ করা যায়। পরবর্তীতে ইন্টারনেট সংযোগ পেলেই স্বয়ংক্রিয়ভাবে 
ক্লাউড সার্ভারের সাথে ব্যাকগ্রাউন্ডে ডেটা সিঙ্ক হয়ে যায়।

২. ফোল্ডার ও ফাইল পরিচিতি (Frontend বনাম Backend ফাইল কোনগুলো)
================================================================================
প্রজেক্টের ফাইলগুলোকে প্রধানত দুটি ভাগে ভাগ করা যায়:

[ক] FRONTEND ফাইলসমূহ (ব্যবহারকারীর স্ক্রিনে যা চলে):
---------------------------------------------------
1. khoroch/index.html
   - এটি পুরো অ্যাপের হৃৎপিণ্ড। সম্পূর্ণ HTML ডিজাইন, Tailwind/CSS স্টাইলিং এবং 
     হিসাব-নিকাশ, ড্যাশবোর্ড, ফিল্টারিং, ব্যাকআপ, অফলাইন লোকালস্টোরেজ হ্যান্ডলিং—সবকিছু 
     এই একটি ফাইলে অত্যন্ত সুশৃঙ্খলভাবে রাখা।
2. khoroch/sw.js
   - সার্ভিস ওয়ার্কার স্ক্রিপ্ট। ব্রাউজারে বা PWA হিসেবে সম্পূর্ণ অফলাইনে অ্যাপ ক্যাশ 
     করে রাখার দায়িত্ব এর।
3. khoroch/manifest.json
   - PWA কনফিগারেশন ফাইল। ফোনের হোমস্ক্রিনে অ্যাপের নাম, কালার ও আইকন দেখায়।
4. khoroch/icon-*.png
   - অ্যাপের বিভিন্ন সাইজের লোগো ও আইকনসমূহ।

[খ] BACKEND ফাইলসমূহ (সার্ভারে ব্যাকগ্রাউন্ডে যা চলে):
-----------------------------------------------------
1. khoroch/api.php
   - মূল ক্লাউড ইঞ্জিন। মোবাইল অ্যাপ বা ব্রাউজার থেকে পাঠানো লগইন, পাসওয়ার্ড হ্যাশিং, 
     রেজিস্ট্রেশন এবং মাল্টি-ডিভাইস খরচের হিসাব SQLite ডেটাবেসে সংরক্ষণ ও সিঙ্ক করে।
2. khoroch/admin.php
   - সুরক্ষিত অ্যাডমিন প্যানেল। কতজন ব্যবহারকারী আছে দেখা, নোটিশ পাঠানো বা 
     সিস্টেম ব্রডকাস্ট নিয়ন্ত্রণ করার জন্য।
3. khoroch/.htaccess
   - অ্যাপাচি সার্ভার সিকিউরিটি রুলস। সরাসরি ডেটাবেস ডাউনলোড বা হ্যাক রোধ করে।
4. Dockerfile
   - Render.com-এ ১-ক্লিকে Apache + PHP 8.2 + SQLite চালুর স্বয়ংক্রিয় কনফিগ।

[গ] ANDROID ও বিল্ড ফাইলসমূহ:
----------------------------
1. android/
   - পূর্ণাঙ্গ Capacitor 6 অ্যান্ড্রয়েড সোর্স প্রজেক্ট।
2. capacitor.config.json
   - ওয়েব অ্যাপকে কীভাবে অ্যান্ড্রয়েড অ্যাপে রূপান্তর করা হবে তার কনফিগ।
3. .github/workflows/android-build.yml
   - GitHub Actions অটোমেশন স্ক্রিপ্ট (ক্লাউডে নিজে নিজে APK বানায়)।

৩. গিটহাবে Frontend + Backend দুটোই থাকলে APK বানালো কেমনে? Backend-এর কাজ কী?
================================================================================
প্রশ্ন: "অ্যান্ড্রয়েড তো PHP চালাতে পারে না, তাহলে গিটহাবে PHP ফাইল থাকা সত্ত্বেও 
        সে APK কীভাবে বানালো? ব্যাকএন্ডের কি কোনো দরকার আছে?"

উত্তর:
ক) সে APK কীভাবে বানালো?
   - আমরা এই প্রজেক্টে Capacitor ফ্রেমওয়ার্ক ব্যবহার করেছি।
   - বিল্ড কমান্ড (`npm run cap:sync`) রান হলে সে শুধুমাত্র ফ্রন্টএন্ড 
     (index.html, sw.js, manifest.json এবং আইকন) কপি করে অ্যান্ড্রয়েড অ্যাপের 
     ভেতরে ঢুকিয়ে দেয়।
   - আর ব্যাকএন্ড ফাইলগুলো (api.php, admin.php, .htaccess) আমরা স্ক্রিপ্ট দিয়ে 
     স্বয়ংক্রিয়ভাবে APK থেকে সম্পূর্ণ বাদ (exclude) দিয়ে দিয়েছি!
   - ফলে Gradle কোনো ঝামেলা ছাড়াই একটি ফুল-স্পিড নেটিভ অ্যান্ড্রয়েড APK বানিয়ে ফেলে।

খ) তাহলে Backend-এর কী কাজ?
   - Backend হলো আপনার নিরাপদ "ক্লাউড লকার"।
   - যদি ব্যাকএন্ড না থাকে, তাহলে অ্যাপটি চলবে কিন্তু শুধুই সেই একটি ফোনেই সীমাবদ্ধ থাকবে। 
     ফোন নষ্ট হলে বা চুরি হলে সব খরচের হিসাব চিরতরে মুছে যাবে।
   - কিন্তু ব্যাকএন্ড (api.php) থাকলে ব্যবহারকারী ইমেইল দিয়ে লগইন করলেই সব হিসাব 
     ক্লাউডে সেভ থাকে। নতুন ফোনে লগইন করলেই নিমিষে সব হিসাব ফেরত আসে!

৪. Public ফোল্ডারে কী আছে? ওটা কি বারবার এডিট করতে হয়?
================================================================================
👉 না, আপনাকে `public/` ফোল্ডারে ম্যানুয়ালি কিছু এডিট করতে হবে না!

- এই প্রজেক্টে আসল সোর্স ফাইল থাকে `khoroch/` ফোল্ডারে।
- `public/khoroch/` ফোল্ডারে শুধু প্রিভিউ দেখার একটি কপি থাকে।
- আপনি যখনই `npm run cap:sync` রান করবেন, `khoroch/` থেকে স্বয়ংক্রিয়ভাবে ফাইলগুলো 
  `public/khoroch/` এবং অ্যান্ড্রয়েড ফোল্ডারে কপি হয়ে যায়।
- তাই যেকোনো পরিবর্তনের জন্য শুধুই `khoroch/index.html` এডিট করাই যথেষ্ট।

৫. হোস্টিংয়ে ওয়েবসাইট লাইভ করার নিয়ম
================================================================================
আপনি যদি ওয়েবসাইট হিসেবে এটিকে চালাতে চান:
১. যেকোনো সাধারণ cPanel বা PHP হোস্টিং নিন।
২. File Manager-এ ঢুকে `public_html` ফোল্ডারের ভেতর `khoroch/` ফোল্ডারের ভেতরের 
   সমস্ত ফাইল (`index.html`, `api.php`, `admin.php`, `.htaccess`, আইকন ইত্যাদি) আপলোড করুন।
৩. ব্রাউজারে `https://yourdomain.com/admin.php` খুলে অ্যাডমিন পাসওয়ার্ড সেট করুন।
৪. ব্যাস! ব্যবহারকারীরা ব্রাউজারে `https://yourdomain.com/` লিখলেই অ্যাপ চালু হবে।

৬. কেন InfinityFree / ByetHost (unaux.com, hstn.me) দিয়ে মোবাইল অ্যাপ চলে না?
================================================================================
সমস্যা: "reg করে আবার লগইন করলে বলে account nei / already কিন্তু ভিতরে লগইন হয় নাহ" 
        অথবা "সার্ভারে যোগাযোগ করা যাচ্ছে না"।

কারণ:
- unaux.com, hstn.me, epizy.com—এই সবগুলোই ByetHost কোম্পানির ফ্রি হোস্টিং।
- তাদের সব সার্ভারে একটি বাধ্যতামূলক **"aes.js" অ্যান্টি-বট ফায়ারওয়াল** থাকে।
- কম্পিউটার বা ফোনের ব্রাউজার সেই জাভাস্ক্রিপ্ট কুকি সলভ করতে পারে, কিন্তু 
  **মোবাইল অ্যাপ (Android APK)** সরাসরি JSON ডেটা আশা করে।
- অ্যাপ যখনই রিকোয়েস্ট পাঠায়, ByetHost সার্ভার JSON না দিয়ে সেই HTML ফায়ারওয়াল 
  ছুড়ে মারে। এর ফলে অ্যাপের ভেতর "Invalid JSON" এরর দিয়ে আটকে থাকে।
- ইনফিনিটি-ফ্রির অফিসিয়াল নিয়মেই বলা আছে: ফ্রি হোস্টিং কোনো মোবাইল অ্যাপ বা API-এর 
  জন্য ব্যবহার করা নিষিদ্ধ।

৭. Render.com-এ ফ্রিতে ব্যাকএন্ড API চালু করার নিয়ম (Docker সহ)
================================================================================
Render.com-এ কোনো বট-ব্লকার নেই, এটি ১০০% আসল REST API সাপোর্ট করে এবং সম্পূর্ণ ফ্রি!

ধাপসমূহ:
১. https://render.com এ যান এবং "Sign in with GitHub" দিয়ে লগইন করুন।
২. উপরে নীল বোতাম `New +` এ ক্লিক করে `Web Service` বেছে নিন।
৩. "Build and deploy from a Git repository" সিলেক্ট করে আপনার `Khoros-khata` 
   রিপোজিটরিটি `Connect` করুন।
৪. ফর্ম ফিলাপ করুন:
   - Name: khoroch-api (বা পছন্দের নাম)
   - Region: Singapore বা Frankfurt
   - Language / Runtime: **Docker** সিলেক্ট করুন। (আমরা প্রোজেক্টে Dockerfile দিয়েছি)
   - Root Directory: **একদম খালি/ফাঁকা** রাখবেন।
   - Build Command / Start Command: কিচ্ছু লাগবে না (ডকার নিজেই চালাবে)।
   - Instance Type: **Free** ($0/month) রেডিও বাটন সিলেক্ট করুন।
৫. নিচে `Create Web Service` বাটনে চাপুন।
৬. ১-২ মিনিটে সার্ভিসটি Live হয়ে যাবে এবং আপনি একটি লাইভ লিংক পাবেন:
   যেমন: `https://khoroch-api.onrender.com`
৭. ব্রাউজারে টেস্ট করতে খুলুন:
   `https://khoroch-api.onrender.com/api.php?a=config`
   (সুন্দর JSON ডেটা দেখতে পেলেই বুঝবেন আপনার API একদম তৈরি!)

================================================================================
৮. অ্যাডমিন প্যানেলে পাসওয়ার্ড সেট করার নিয়ম (admin.php)
================================================================================
Render-এ অ্যাডমিন প্যানেল খুললে যদি বলে: "সেটআপ দরকার: ADMIN_PASS পরিবর্তন করুন"

সমাধান:
১. আপনার GitHub-এ `khoroch/admin.php` ফাইলটি এডিট করুন (পেন্সিল ✏️ আইকন)।
২. একদম উপরে ৫ নম্বর লাইনে দেখুন:
   const ADMIN_PASS = 'CHANGE_ME_NOW';

৪. সেভ (Commit) করলেই Render স্বয়ংক্রিয়ভাবে আপডেট করে নেবে।
৫. এবার `https://your-api.onrender.com/admin.php` পেজে গিয়ে আপনার দেওয়া 
   পাসওয়ার্ডটি লিখে সরাসরি অ্যাডমিন প্যানেলে ঢুকে যান।

হেডারের ছোট সবুজ ডট দিয়ে সুন্দরভাবে সিঙ্ক স্ট্যাটাস বোঝা যাবে।

১২. জাভাস্ক্রিপ্ট সিনট্যাক্স এরর (SyntaxError) এড়ানোর নিয়ম
================================================================================
মনে রাখবেন, জাভাস্ক্রিপ্ট ফাইলে কোড ডিলিট করার সময় যদি কোনো সেকেন্ড ব্র্যাকেট `}` 
মুছে যায়, তাহলে পুরো জাভাস্ক্রিপ্ট ক্র্যাশ করবে এবং কোনো বোতাম বা পেজ নেভিগেশন 
কাজ করবে না।

সবসময় লক্ষ্য রাখবেন `dot('ok');` এর ঠিক পরেই যেন বন্ধনী `}` থাকে:
```javascript
  SY.fail=0;
  SY.err='';
  dot('ok');
}
if(ch||rejCount>0)go()}
```

১৪. অ্যাডমিন প্যানেল থেকে ইন-অ্যাপ আপডেট (In-App Update) সিস্টেম

আপনার সুবিধার জন্য অ্যাডমিন প্যানেলে নতুন "অ্যাপ আপডেট" ট্যাব যুক্ত করা হয়েছে!

[ক] এটি কীভাবে কাজ করে?
- অ্যাডমিন প্যানেলে ঢুকে "অ্যাপ আপডেট" ট্যাবে যান।
- "অ্যাপ আপডেট পপআপ চালু রাখুন" চেকবক্স অন করুন।
- নতুন ভার্সন (যেমন: 1.1.0) এবং বিল্ড নম্বর (যেমন: 2) দিন।
- ডাউনলোড লিংক ঘরে আপনার নতুন APK-এর ডাউনলোড লিংক (Google Drive, GitHub Releases, 
  MediaFire ইত্যাদি) বসিয়ে দিন।
- সেভ বাটনে চাপুন।

[খ] শুধুমাত্র অ্যান্ড্রয়েড অ্যাপে কেন দেখাবে (ওয়েবসাইটে নয়)?
- কোডে `API_CONFIG.isNativePlatform()` দিয়ে কঠোরভাবে চেক করা হয়।
- ফলে যদি কেউ কম্পিউটারে বা মোবাইলের ক্রোম ব্রাউজারে সাইট খোলে, তার স্ক্রিনে 
  কখনোই এই আপডেট পপআপ আসবে না।
- শুধুমাত্র যারা ফোনে ইনস্টল করা Android APK ব্যবহার করছে, শুধু তাদের স্ক্রিনেই 
  এই ইন-অ্যাপ আপডেট পপআপ আসবে!

[গ] বাধ্যতামূলক আপডেট (Force Update):
- যদি আপনি চান যে ব্যবহারকারী এই নতুন ভার্সনটি আপডেট না করা পর্যন্ত পুরনো অ্যাপ 
  আর চালাতেই পারবে না—তাহলে "বাধ্যতামূলক আপডেট (Force Update)" চেকবক্স অন করে সেভ করুন।
- এতে ব্যবহারকারীর স্ক্রিনে কোনো ক্লোজ বাটন বা "পরে করব" বোতাম থাকবে না এবং ব্যাক বাটন 
  চাপলেও পপআপ বন্ধ হবে না। তাকে অবশ্যই "ইনস্টল করুন" চেপে নতুন ভার্সনে যেতে হবে!
- আর যদি Force Update বন্ধ থাকে, তাহলে ব্যবহারকারী "পরে করব" চেপে সাময়িকভাবে 
  অ্যাপ চালানো চালিয়ে যেতে পারবে।

১৫. নতুন রেজিস্ট্রেশন পেইজ, অ্যাপ্রুভাল সিস্টেম ও প্রিমিয়াম UI আপডেট

[ক] আলাদা রেজিস্ট্রেশন পেইজ (Full Name ও Display Name সহ):
- লগইন স্ক্রিনে এখন দুটি আলাদা ট্যাব রয়েছে: `🔐 লগইন` এবং `📝 নতুন অ্যাকাউন্ট`।
- নতুন অ্যাকাউন্ট খোলার পেইজে রয়েছে:

  ২. ডিসপ্লে নাম (Display Name - অ্যাপের হোমস্ক্রিনে যে নাম দেখাবে)
  ৩. ইমেইল অ্যাড্রেস (Email)
  ৪. পাসওয়ার্ড (৮+ অক্ষর) এবং পাসওয়ার্ড দেখার আইকন (Show/Hide Password)
  ৫. পাসওয়ার্ড নিশ্চিত করুন (Confirm Password)

[খ] ৩টি রেজিস্ট্রেশন মোড (অ্যাডমিন প্যানেল > সেটিংস থেকে নিয়ন্ত্রণযোগ্য):
১. সবার জন্য খোলা (Open Mode):
   - ইউজার রেজিস্ট্রেশন করার সাথে সাথে অ্যাকাউন্ট তৈরি হয়ে লগইন পেইজে নিয়ে যাবে এবং

২. অনুমোদন সাপেক্ষে (Approval Mode):
   - ইউজার রেজিস্ট্রেশন করলে পপআপ ও নোটিশ দেখাবে: "আপনার অ্যাকাউন্ট তৈরির আবেদন সফল

     ইমেইলে জানানো হবে।"
   - অ্যাডমিন প্যানেলের "ব্যবহারকারী" ট্যাবে ইউজারের নামের পাশে "অনুমোদন দিন" বাটন আসবে।
৩. বন্ধ (Closed Mode):
   - রেজিস্ট্রেশন পেইজে স্পষ্ট লাল ব্যানারে লেখা থাকবে যে বর্তমানে নতুন অ্যাকাউন্ট নিবন্ধন বন্ধ আছে।

  সক্রিয় থাকে। ইউজার নিজে লগআউট না করলে অ্যাপ বন্ধ করলেও বা রিস্টার্ট দিলেও অটো লগআউট হবে না।

১৬. একাউন্ট উধাও হয়ে যাওয়া এবং অ্যাডমিন প্যানেল রিসেট সমস্যার ১০০% স্থায়ী সমাধান!
================================================================================
[ক] সমস্যাটি কেন হচ্ছিল? (Root Cause):
- Render.com-এর Free Tier সার্ভারে ১৫ মিনিট কোনো ভিজিটর না থাকলে সার্ভার নিজে নিজে 
  "Sleep / Spin Down" হয়ে যায় অথবা GitHub-এ নতুন কোড পুশ করলে Docker Container রিবিল্ড হয়।
- তখন সার্ভারের ভেতরের অস্থায়ী ফাইল (`data/khoroch.sqlite`) মুছে যেত। ফলে কিছুক্ষণ পর 
  ঢুকলে বলতো "অ্যাকাউন্ট নেই" এবং `admin.php`-তে ঢুকলে "ডেটাবেস নেই" বা নতুন থেকে শুরু হতো!

[খ] নতুন ৩-স্তরের অটো-রিকভারি সিস্টেম (3-Layer Auto-Heal Architecture):
১. ইউজার অ্যাকাউন্ট ও ডাটা অটো-রিকভারি (Zero-Config Client Account Vault):
   - ইউজার যখন রেজিস্ট্রেশন বা লগইন করে, তার এনক্রিপ্টেড অ্যাকাউন্ট ভল্ট ও সকল খরচের হিসাব 
     ফোনে/ব্রাউজারে সুরক্ষিত থাকে।
   - সার্ভার রিস্টার্ট হয়ে ডাটাবেস মুছে গেলেও ইউজার যখনই অ্যাপে ঢুকবে বা লগইন করবে, অ্যাপ 
     স্বয়ংক্রিয়ভাবে ব্যাকগ্রাউন্ডে তার অ্যাকাউন্ট, সেশন টোকেন এবং সম্পূর্ণ খরচের ডাটা সার্ভারে 
     পুনরায় রিস্টোর (`resync_all`) করে নেবে! ইউজার কখনোই লগআউট হবে না বা "অ্যাকাউন্ট নেই" দেখবে না।

২. অ্যাডমিন প্যানেল অটো-ইনিশিয়ালাইজ ও ব্রাউজার ভল্ট (Admin Auto-Restore):
   - `admin.php` ফাইলে আগে ডাটাবেস না থাকলে "ডেটাবেস নেই — আগে সাইট একবার খুলুন" দেখাতো। 
     এখন `admin.php` নিজেই স্বয়ংক্রিয়ভাবে ডাটাবেস ও টেবিল তৈরি করে নেয়!
   - এছাড়া অ্যাডমিনের সকল সেটিংস (নোটিশ, সোশ্যাল লিংক, ব্র্যান্ডিং, মেইনটেন্যান্স, অ্যাপ আপডেট) 
     অ্যাডমিনের ব্রাউজার ভল্টে (`kh_adm_vault`) ব্যাকআপ থাকে এবং সার্ভার রিসেট হলে অ্যাডমিন প্যানেলে 
     ঢোকার সাথে সাথে স্বয়ংক্রিয়ভাবে সব সেটিংস আগের অবস্থায় ফিরে আসে।

৩. স্থায়ী ক্লাউড ডাটাবেস সিঙ্ক (GitHub Secret Gist Auto-Backup - ঐচ্ছিক কিন্তু রিকমেন্ডেড):
   - আপনি চাইলে অ্যাডমিন প্যানেল -> "সেটিংস" ট্যাবে গিয়ে `☁️ স্থায়ী ক্লাউড ডাটাবেস সিঙ্ক` বক্সে 
     আপনার একটি GitHub Personal Access Token (`ghp_...` যার শুধুমাত্র `gist` টিক দেওয়া আছে) 
     দিয়ে সেভ করতে পারেন (অথবা Render.com -> Environment-এ `GITHUB_TOKEN` নামে যোগ করতে পারেন)।
   - এটি দিলে সার্ভার প্রতিবার নতুন ইউজার রেজিস্ট্রেশন, লগইন বা অ্যাডমিন সেটিংস পরিবর্তনের সাথে সাথে 
     আপনার গোপন GitHub Gist-এ পুরো SQLite ডাটাবেস ব্যাকআপ রাখবে এবং সার্ভার স্লিপ থেকে জাগলে 
     ১ সেকেন্ডের মধ্যে সব ইউজার ও অ্যাডমিন ডাটা ক্লাউড থেকে রিস্টোর করে নেবে!

১৮. GitHub-এ APK কোন ফোল্ডারের কারণে তৈরি হয় এবং সব ফাইল ও ফোল্ডারের কাজ
================================================================================

[ক] GitHub-এ APK মূলত কোন ফোল্ডারগুলোর কারণে তৈরি হচ্ছে?
GitHub Actions যখন অটোমেটিক আপনার জন্য Android APK তৈরি করে, তখন সে নিচের ফোল্ডার ও ফাইলগুলো ব্যবহার করে:
১. `.github/workflows/android-build.yml` -> এই ফাইলটিই GitHub-কে নির্দেশ দেয় কীভাবে ধাপে ধাপে APK বানাতে হবে।
২. `khoroch/` ফোল্ডার -> আপনার অ্যাপের আসল কোড (`index.html`, `manifest.json`, `sw.js`) এখান থেকে নেওয়া হয়।
৩. `android/` ফোল্ডার -> এটি হলো আসল Android Studio প্রজেক্ট। `khoroch/index.html` ফাইলটি কপি হয়ে 
   `android/` ফোল্ডারের ভেতরে ঢুকে APK তৈরি হয়।
৪. `package.json`, `package-lock.json` এবং `capacitor.config.json` -> এই ৩টি ফাইল `khoroch/` ফোল্ডারের 
   কোডকে `android/` ফোল্ডারের সাথে ব্রিজ (Capacitor Sync) করতে সাহায্য করে।

[খ] আপনি যদি GitHub-এ শুধু প্রয়োজনীয় ফোল্ডার রাখতে চান, তাহলে কী কী রাখবেন?
আপনি যদি আপনার GitHub রিপোজিটরি একদম ক্লিন রাখতে চান (যাতে Render.com সার্ভার + GitHub APK Build 
দুটোই ১০০% কাজ করে), তাহলে শুধুমাত্র নিচের ৭টি জিনিস GitHub-এ রাখলেই চলবে:
  ✅ ১. `.github/` ফোল্ডার (অটোমেটিক APK বিল্ড করার জন্য)
  ✅ ২. `android/` ফোল্ডার (অ্যান্ড্রয়েড অ্যাপের মূল স্ট্রাকচার)
  ✅ ৩. `khoroch/` ফোল্ডার (আপনার মূল অ্যাপ, `api.php`, `admin.php`, `db_cloud.php`)
  ✅ ৪. `Dockerfile` (Render.com-এ আপনার PHP সার্ভার চালানোর জন্য)
  ✅ ৫. `capacitor.config.json` (অ্যাপের নাম ও প্যাকেজ কনফিগারেশন)
  ✅ ৬. `package.json` (Capacitor সিঙ্ক কমান্ড চালানোর জন্য)
  ✅ ৭. `package-lock.json` (GitHub Actions-এ দ্রুত প্যাকেজ ইনস্টলের জন্য)

*(বি.দ্র.: `src/`, `public/`, `vite.config.ts`, `tsconfig.json`, `metadata.json` এবং বাহিরের `index.html`—
এগুলো শুধুমাত্র Google AI Studio-র প্রিভিউ ড্যাশবোর্ডের জন্য। এগুলো GitHub থেকে ডিলিট করলেও আপনার 
APK বা Render সার্ভারে কোনো সমস্যা হবে না, আবার রেখে দিলেও কোনো ক্ষতি নেই।)*

১. `khoroch/` ফোল্ডার (আপনার মূল ওয়েব অ্যাপ ও ব্যাকএন্ড সার্ভার - ১৩টি ফাইল):

- `khoroch/icon-192.png` : সাধারণ অ্যান্ড্রয়েড ও ব্রাউজারের জন্য ১৯২×১৯২ পিক্সেলের অ্যাপ আইকন।

- `.gitignore` : Git বা GitHub-এ আপলোড করার সময় অপ্রয়োজনীয় বড় ফোল্ডার (`node_modules/`, `dist/`, `.sqlite` ডাটাবেস) যেন আপলোড না হয় তা নিশ্চিত করে।
- `.env.example` : এনভায়রনমেন্ট ভ্যারিয়েবলের নমুনা ফাইল।
- `README.txt` : বাংলায় লেখা এই সম্পূর্ণ মাস্টার গাইডবুক।

৫. AI Studio প্রিভিউ ফোল্ডার ও ফাইল (শুধুমাত্র AI Studio ড্যাশবোর্ডের জন্য):

- `src/` (`App.tsx`, `main.tsx`, `index.css`) : Google AI Studio-তে ডানপাশের প্রিভিউ স্ক্রিনে রিপোর্ট ও জিপ ডাউনলোড বাটন দেখানোর React কোড।

- `index.html` (রুট ফোল্ডারের), `vite.config.ts`, `tsconfig.json`, `metadata.json` : AI Studio-র প্রিভিউ সার্ভার চালানোর ফাইল। (আপনার মূল অ্যাপ বা APK-তে এগুলোর কোনো কাজ নেই)।

১৯. cPanel বা অন্য যেকোনো পেইড হোস্টিংয়ে ব্যাকএন্ড হোস্ট করার নিয়ম
================================================================================
আপনি যদি Render.com-এর বদলে **cPanel** বা অন্য কোনো ওয়েব হোস্টিংয়ে ব্যাকএন্ড রাখতে চান, 
তাহলে কাজ আরও সহজ:

১. cPanel-এর সুবিধা:
   - cPanel-এর স্টোরেজ স্থায়ী (Permanent SSD), তাই সার্ভার কখনোই Sleep হয় না এবং 
     `data/khoroch.sqlite` ডাটাবেস কখনোই ডিলিট বা রিসেট হয় না!
   - আলাদা করে কোনো MySQL Database বা User খোলারও প্রয়োজন নেই।

২. cPanel-এ কোন ফাইলগুলো আপলোড করবেন?
   - পুরো জিপ আপলোড করতে হবে না। শুধুমাত্র **`khoroch/`** ফোল্ডারের ভেতরের ফাইলগুলো 
     (`index.html`, `api.php`, `admin.php`, `db_cloud.php`, `manifest.json`, `sw.js`, `.htaccess` ও আইকনগুলো) 
     আপনার cPanel-এর `public_html/` ফোল্ডারে (অথবা সাব-ফোল্ডারে যেমন `public_html/khoroch/`) আপলোড করুন।

৩. কোডে কী পরিবর্তন করবেন?
   - `khoroch/admin.php` (লাইন ৫): `const ADMIN_PASS = 'আপনার_গোপন_পাসওয়ার্ড';` দিন।
   - `khoroch/index.html` (লাইন ১৪৭২): আপনার cPanel ডোমেইনের লিংক দিন, যেমন:
     `PRODUCTION_API_URL:'https://yourdomain.com/api.php',`
   - এরপর GitHub-এ কোড পুশ করে APK বিল্ড করে নিলে আপনার Android অ্যাপ সরাসরি cPanel সার্ভারের সাথে চলবে!
