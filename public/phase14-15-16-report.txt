1. PHASE 14 REPORT — APPLICATION-WIDE SECURITY & PERFORMANCE
================================================================================

1.1 Phase 14 Summary
--------------------
Completed a comprehensive application-wide security and performance audit and hardening pass across the shared frontend (`public/khoroch/index.html` & `khoroch/index.html`), the PHP API backend (`api.php`), the existing Admin Panel (`admin.php`), the Service Worker (`sw.js`), and server configuration (`.htaccess`), while preserving all approved functionality from Phases 1–13.

1.2 Security Findings & Fixes
-----------------------------
- Frontend DOM/Template XSS Hardening (`public/khoroch/index.html`, `khoroch/index.html`):
  * Upgraded `esc()` to escape single quotes (`'` -> `&#39;`) in addition to `&`, `<`, `>`, and `"`.
  * Escaped toast notification messages in `toast(m, undo)` (`<span>${esc(m)}</span>`).
  * Escaped all dynamic attributes and record IDs rendered in `eitem()`, `go()`, `copts()`, `vl()`, `vr()`, `vc()`, `openForm()`, `ask()`, and `groupSheet()`.
  * Enforced strict 5 MB file size limit (`f.size > 5242880`) and structural array validation (`Array.isArray(d.exps)`, `Array.isArray(d.cats)`) on JSON backup import `imp(f)`.
- API Input, Method & Error Hardening (`public/khoroch/api.php`, `khoroch/api.php`):
  * Added `redactApiLog()` on `set_error_handler` and exception logger so sensitive fields (`password`, `passwd`, `hash`, `token`, `Bearer`, `delete_code`, `admin_hash`, `ADMIN_PASS`) are automatically redacted before writing to `data/error.log`.
  * Enforced strict `POST`-only method check (`HTTP 405 Method Not Allowed`) on state-changing actions (`register`, `login`, `logout`, `passwd`, `delacct`, `sync`).
  * Capped password input length at 200 characters (preventing bcrypt CPU exhaustion DoS) and email length at 254 characters.
  * Added strict API response security headers: `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=(), usb=()`, and HTTPS-aware `Strict-Transport-Security: max-age=31536000; includeSubDomains`.
- Admin Panel URL & Log Hardening (`public/khoroch/admin.php`, `khoroch/admin.php`):
  * Hardened `cleanUrl()` to explicitly reject dangerous URI schemes (`javascript:`, `data:`, `vbscript:`, `file:`, `blob:`) and enforce `^https?://` on web links.
  * Added `redactSensitiveLog()` to `set_error_handler` and `set_exception_handler` in `admin.php`.
  * Added `Permissions-Policy` and HTTPS-aware `Strict-Transport-Security` headers.

1.3 Performance Findings & Fixes
--------------------------------
- SQLite Engine Optimization (`api.php` & `admin.php`):
  * Added `PRAGMA synchronous=NORMAL;` and `PRAGMA temp_store=MEMORY;` alongside `PRAGMA journal_mode=WAL;` and `PRAGMA busy_timeout=8000;`.
- Single-Query Public Config Load (`api.php?a=config`):
  * Consolidated 7 separate `SELECT v FROM settings WHERE k=...` queries in `a=config` into a single `SELECT k, v FROM settings WHERE k IN ('notices','social','socmode','poll','welcome','brand','maint')` query.
- Elimination of N+1 Category Lookups in Sync (`api.php?a=sync`):
  * Replaced per-expense `SELECT category_id FROM expense_categories WHERE user_id=? AND expense_id=?` loop with a single batched `WHERE user_id=? AND expense_id IN (...)` query mapped in memory.

2.3 Hosting Requirements & Permissions Checklist
------------------------------------------------
- Web Server: Apache 2.4+ or LiteSpeed (standard cPanel hosting) with HTTPS (AutoSSL / Let's Encrypt).
- PHP Version: PHP 8.0+ (PHP 8.1 / 8.2 / 8.3 recommended).
- Required PHP Extensions: `pdo`, `pdo_sqlite`, `sqlite3`, `json`, `session`, `mbstring`, `openssl` / `hash`.
- Recommended Permissions:
  * Application directory (`public_html/` or `public_html/khoroch/`): `0755`
  * Static & PHP files (`index.html`, `api.php`, `admin.php`, `sw.js`, `manifest.json`, `.htaccess`, `*.png`): `0644`
  * `data/` directory: `0750` (auto-created if absent)
  * `data/khoroch.sqlite` and `data/error.log`: `0640`

2.4 Step-by-Step cPanel Deployment & Safe Upgrade Guide
-------------------------------------------------------
- Fresh Deployment:
  1. Upload contents of `public/khoroch/` (including hidden `.htaccess`) to `public_html/` (root) or `public_html/khoroch/` (subdirectory).
  2. Edit `admin.php` line 5 (`const ADMIN_PASS = 'CHANGE_ME_NOW';`) to a strong password before first login, and optionally rename `admin.php` to a private filename (e.g., `panel-x7k2.php`).
  3. Open `https://your-domain.com/khoroch/api.php?a=health` and verify `{"ok":true}`.
  4. Log in to `admin.php` once (which hashes the password into SQLite `settings('admin_hash')`), then change the password again from inside the Admin Panel Security tab.
- Safe Non-Destructive Upgrade of Existing Installation:
  1. In `admin.php`, click "ডাটাবেস ডাউনলোড (.sqlite)" and "সব সেটিংস এক্সপোর্ট (.json)" to save a pre-upgrade backup.
  2. Upload updated code files (`index.html`, `api.php`, `admin.php`, `sw.js`, `manifest.json`, `.htaccess`, `*.png`).
  3. NEVER overwrite or delete the live `data/` folder or `data/khoroch.sqlite`. `api.php` and `admin.php` use `CREATE TABLE IF NOT EXISTS` and safe `ALTER TABLE` checks that preserve all existing users, expenses, groups, categories, and settings.
