3. API INTEGRATION DETAILS
--------------------------------------------------------------------------------
1. Centralized Resolver & Fail-Fast URL Handling:
   - Web/PWA Runtime: Resolves dynamically to relative "api.php" or configured host.
   - Capacitor Android Runtime: Resolves to window.KHOROCH_API_URL or stored kh_api_url.
     If an unconfigured/placeholder domain (e.g. yourdomain.com) is detected,
     API_CONFIG immediately throws API_URL_NOT_CONFIGURED.
   - Frontend Catch Blocks: Detect API_URL_NOT_CONFIGURED and inform the user
     ("API URL কনফিগার করা নেই। অনুগ্রহ করে সঠিক ব্যাকএন্ড URL দিন।") rather than
     masking it as a network failure.

2. Bearer Authentication Header Integration:
   - Added centralized `authHeaders(extraHeaders)` helper:
     `Authorization: Bearer <tok>` is attached to every authenticated fetch:
     - sync()
     - ping()
     - chgPass()
     - delAcct()
     - flush()
     - logout()
   - Fallback body token preserved for backwards compatibility with offline sendBeacon.

3. Comprehensive HTTP Status Error Handling:
   - HTTP 401 Unauthorized: Clears expired/revoked session via `logout(true)` and prompts login.
   - HTTP 403 Forbidden: Distinguishes untrusted_origin (CORS 403), revoked/disabled tokens,
     and cross-user unauthorized access.
   - HTTP 404 Not Found: Clearly reports "API পাওয়া যায়নি (কোড 404)".
   - HTTP 500+ Server Error: Gracefully surfaces "সার্ভার ত্রুটি (কোড <status>)" with retry backoff.
   - Invalid JSON: Catches non-JSON / HTML server crashes and reports "সার্ভার ঠিকমতো উত্তর দেয়নি (Invalid JSON)".


4. DATA SYNCHRONIZATION INTEGRATION & DATA LOSS PREVENTION
--------------------------------------------------------------------------------
- Optimistic Local Persistence: All local edits, creations, and deletions immediately persist
  to localStorage (`_d = 1`).
- Atomic Server Confirmation: Local dirty flags are ONLY cleared when server responds with
  matching confirmation (`confP`, `confC`, `confE`, `confR`).
- Rejected Expense Recovery: Unmapped or foreign-group expenses are marked `_rej = 1` and
  retained locally with `_d = 1`. A warning toast instructs the user to assign a valid group.
- Deletion Tombstones: Tombstone records (`deleted = 1`) propagate bidirectionally without
  resurrecting deleted items.
- Duplicate Prevention: Backend relies on composite primary keys `(user_id, id)` with
  `ON CONFLICT(user_id, id) DO UPDATE`, guaranteeing idempotency across network retries.
- Offline Retry Backoff: Exponential backoff (`Math.min(60000, 5000 * 2^fail)`) schedules
  automatic retry without locking the UI.
