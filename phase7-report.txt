3. EXACT CORS ALLOWLIST CONFIGURATION
--------------------------------------------------------------------------------
Wildcard ("*") origin access is strictly forbidden. The backend implements `isAllowedOrigin($origin)`
which validates incoming origins against an explicit, secure allowlist:

1. Capacitor Android Native Webview:
   - "capacitor://localhost"
   - "https://localhost"

2. Development Environments:
   - "http://localhost" (and any localhost port, e.g. http://localhost:3000, http://localhost:5173)
   - "http://127.0.0.1" (and any 127.0.0.1 port, e.g. http://127.0.0.1:3000)

3. Production Web Deployment:
   - Same-origin matching: `parse_url($origin, PHP_URL_HOST) === $_SERVER['HTTP_HOST']`
   - Configured production domain: Retrieved securely from SQLite `settings` table (`cors_origin` or `app_domain`)
     or via `APP_ORIGIN` environment constant.

Behavior for Allowed Origins:
- The exact allowed origin is reflected in `Access-Control-Allow-Origin: <origin>`
- `Access-Control-Allow-Credentials: true` is included
- `Vary: Origin` is always emitted to prevent cache poisoning across intermediate proxies

Behavior for Untrusted Origins:
- Never reflected.
- OPTIONS preflight from untrusted origin returns HTTP 403 Forbidden.
- State-changing POST requests from untrusted origin return HTTP 403 Forbidden with `{"ok": false, "error": "untrusted_origin"}`.


4. OPTIONS PREFLIGHT HANDLING DETAILS
--------------------------------------------------------------------------------
- Intercepted at the very top of `api.php` before database connection or token validation.
- Allowed Origin Preflight:
  - Responds immediately with HTTP 204 No Content.
  - Emits:
    - Access-Control-Allow-Origin: <origin>
    - Access-Control-Allow-Credentials: true
    - Access-Control-Allow-Methods: GET, POST, OPTIONS
    - Access-Control-Allow-Headers: Content-Type, Authorization, X-Requested-With
    - Access-Control-Max-Age: 86400 (24-hour preflight cache)
    - Vary: Origin
  - Exits immediately (`exit;`). Guaranteed ZERO database operations, zero token lookups, and zero file writes.
- Untrusted Origin Preflight:
  - Responds with HTTP 403 Forbidden and exits immediately (`exit;`).


5. API RESPONSE & SECURITY HEADERS IMPLEMENTED
--------------------------------------------------------------------------------
Every API response emits:
1. `Content-Type: application/json; charset=utf-8`
2. `Cache-Control: no-store, no-cache, must-revalidate, max-age=0`
3. `Pragma: no-cache`
4. `X-Content-Type-Options: nosniff`
5. `X-Frame-Options: SAMEORIGIN`
6. `Referrer-Policy: strict-origin-when-cross-origin`
7. `X-XSS-Protection: 1; mode=block`
8. `Vary: Origin`

Unsupported HTTP Methods:
- Any method other than GET, POST, or OPTIONS (e.g., PUT, DELETE, PATCH, TRACE)
  is intercepted immediately and returns:
  - HTTP 405 Method Not Allowed
  - `Allow: GET, POST, OPTIONS`
  - JSON payload: `{"ok": false, "error": "method_not_allowed"}`

8. REMAINING RISKS & LIMITATIONS
--------------------------------------------------------------------------------
- Production Domain Configuration: When moving from staging/localhost to a custom domain
  (e.g., https://mykhoroch.com), the administrator should set the `cors_origin` or `app_domain`
  in the `settings` table or via the `APP_ORIGIN` environment variable so cross-origin PWA
  manifest workers or subdomains can access the API if separated.
- No other architectural or security limitations exist. Multi-user isolation, token revocation,
  and CORS hardening are fully active.
