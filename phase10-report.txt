1. CONFLICT RESOLUTION POLICY CORRECTION (PHASE 2 ALIGNMENT)
--------------------------------------------------------------------------------
In accordance with the Phase 2 Architecture Specification (Section 2.D), the conflict
resolution engine in `api.php` has been explicitly audited, corrected, and verified to
enforce deterministic Last-Write-Wins (LWW) with payload/ID tie-breaking and deletion
dominance, fully resolving the previous inconsistency regarding "first-arrival tie-breaking":

Established Phase 2 Deterministic Policy:
1. Different Timestamps:
   - If `incoming.updated > existing.updated`: Incoming write is accepted (LWW).
   - If `incoming.updated < existing.updated`: Existing server record is preserved.
2. Equal Timestamps (`incoming.updated === existing.updated`):
   - Deletions Dominate: Deletion is accepted if `incoming.updated >= existing.updated`.
     A deletion at an equal timestamp always supersedes an active update. An active update
     cannot overwrite a deletion sharing the same timestamp.
   - Deterministic Tie-Breaking: If both conflicting records share the exact same timestamp
     and deletion state, the tie is broken deterministically by string comparison of the
     record payload hash/fingerprint (`strcmp($inHash, $exHash) > 0`).
3. Guaranteed Multi-Device Convergence:
   - Regardless of whether Device A syncs before Device B or vice versa, the server and
     both client devices evaluate to the exact same deterministic winner.
   - Zero reliance on network arrival sequence or transaction race timing.
